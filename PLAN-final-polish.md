artifact users download. This plan is the vet no human will perform afterwards: the
QA checklist is executed against the app installed **from the DMG** (not the dev
build), and the SHIP / DO-NOT-SHIP verdict is committed to the repo.

**Rule, verbatim: "PASS only from actually performing the check — an honest FAIL
committed is worth more than a green lie."**

# DewQRaft

DewQRaft is an offline macOS menu bar utility for crafting QR codes. Click the menu
bar icon, type, and copy or save a scannable code — no network, no accounts, no Dock
icon.

## Features

- Payload types: text/link, Wi-Fi, contact (vCard 3.0), email, phone, SMS
- Live offline rendering (vendored MIT-licensed generator by Kazuhiko Arase)
- PNG and SVG export via copy or native save panel
- Adjustable error correction, export size (512–2048 px), ink/paper colours,
  transparent background
- Popup accent/paper theme, persisted between launches
- [ONLY IF PLAN-save-panel-flow] The popup returns automatically after saving, with
  a visible "Saved" confirmation
- [ONLY IF PLAN-launch-at-login] Optional Launch at Login (right-click the menu bar
  icon)

## Requirements

- macOS 13.0 or later (Apple Silicon or Intel)

## Install

Download `release/DewQRaft-1.1.dmg` (or the `.zip`), drag `DewQRaft.app` into
Applications, and open it. The app is ad-hoc signed (no Apple Developer ID), so on
first launch right-click the app and choose Open if macOS blocks it.

```sh
/bin/zsh scripts/build-mac-app.sh
```

The app bundle is created at `build/DewQRaft.app`.

## Verify

```sh

```

```sh
/bin/zsh scripts/package-release.sh 1.1
```

Creates the ZIP, DMG, and `INSTALL.txt` in `release/`.
```

### Step 3 — Gate, then package

```sh
/bin/zsh scripts/verify.sh
ls /Volumes | grep -i dewqraft && hdiutil detach "/Volumes/DewQRaft 1.1" 2>/dev/null
/bin/zsh scripts/package-release.sh 1.1
```

### Step 4 — Mechanical packaging verification

```sh
hdiutil verify release/DewQRaft-1.1.dmg
rm -rf /tmp/dqz && ditto -x -k release/DewQRaft-1.1.zip /tmp/dqz
codesign --verify --deep --strict /tmp/dqz/DewQRaft.app
defaults read /tmp/dqz/DewQRaft.app/Contents/Info.plist CFBundleShortVersionString
```

Expected: `hdiutil` prints a verified checksum; `codesign` exits 0 silently; the
version prints `1.1`. Do NOT run `spctl -a` — it always rejects ad-hoc-signed apps;
that is expected and must not be "fixed" (there is no Developer ID to sign with).

### Step 5 — Install the REAL artifact and run the QA checklist

```sh
open release/DewQRaft-1.1.dmg
```

Drag `DewQRaft.app` to Applications (replace any older copy; quit it first), eject
the volume, launch `/Applications/DewQRaft.app`. Every QA row below runs against
THIS copy. Rows 3–9 need a physical scanning device (an iPhone/Android camera
pointed at the screen). If no device is available, mark those rows `NOT RUN` — and
the verdict CANNOT be SHIP, because an unscanned QR app is unverified at its core
promise.

## Edge cases a weaker model would miss

- **Bump the version BEFORE packaging** (Step 1 before Step 3). The artifact embeds
  Info.plist; packaging first ships a DMG that claims 1.0. Step 4's `defaults read`
  catches this — if it prints 1.0, redo Step 3, do not hand-edit the artifact.
- **QA runs against the DMG-installed copy, never `build/DewQRaft.app`.** The dev
  build and the artifact are built by the same script, but the artifact is what
  users get — verifying it IS the point of this plan. Launching the wrong copy makes
  every row a green lie.
- **`hdiutil create` can fail if an old DewQRaft volume is mounted** — that is why
  Step 3 detaches first. If packaging fails with a resource-busy error, eject the
  volume and rerun; do not delete `release/` history.
- **The committed `.dmg`/`.zip` are the ONE sanctioned binary commit** (existing
  repo convention: the 1.0 artifacts are already tracked). Leave the 1.0 artifacts
  in place; add the 1.1 ones alongside.
- **`INSTALL.txt` is regenerated by `package-release.sh`** with the new version
  string — commit the regenerated file; do not hand-edit it.
- **README documents shipped behavior only.** Every `[ONLY IF …]` tag must be
  resolved against Step 0's findings, then the tags removed. A README describing a
  feature that a BLOCKERS.md entry says never landed is exactly the dishonesty this
  engagement forbids.
- **`spctl -a` failing is not a defect** — ad-hoc-signed apps always fail Gatekeeper
  assessment; users right-click → Open (documented in README and INSTALL.txt). Do
  not attempt to sign, notarize, or add entitlements.
- **Rows 3–9 without a scanning device: NOT RUN → DO-NOT-SHIP.** A QR generator
  whose codes were never scanned is unverified at its core promise. This is the
  honest outcome, not a failure of yours.
- **If any row FAILs, still commit RELEASE-QA.md with the FAIL recorded**, verdict
  DO-NOT-SHIP, plus a BLOCKERS.md entry. Do not fix-and-rerun inside this plan
  unless the fix is a one-line regression from THIS plan's own steps; regressions
  from earlier plans go to BLOCKERS.md.
